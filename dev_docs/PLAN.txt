マインドマップアプリが欲しい

要件:
・Google Driveを使ってデータを保存、読み込みする
・デザインはシンプルで、機能は最小限
・PCあるいは携帯からアクセスして使う　プラットフォームは不問
・データベースでトピックを管理
　データベースは以下の構成
　1) トピックテーブル
　　ID、トピックタイトル、詳細メモ
　　テーブル列をマインドマップ単位で追加可能
　　追加したテーブルでハイライト表示できる
　2) 接続テーブル
　　ID、接続する2トピックのID、タイプ(線、矢印、逆矢印、双方向矢印)、メモ
　　テーブル列を追加可能
　3) トピック表示テーブル
　　トピックID、ノード形状、位置、サイズ、背景色、文字色
　4) 接続表示テーブル
　　接続ID、スタイル(実線、破線、点線)、色、太さ
　5) 変更履歴テーブル
　　変更対象テーブル、ユーザ、日時、区分(作成、削除、変更)、変更した列、新データ
　　3、4の変更は記録しない
　　マインドマップ自体の作成、別名保存も記録する
　6) テンポラリ変更履歴テーブル: アプリが持つ
　　3、4の変更も保存する
　　マインドマップの保存時に、これから3、4の内容を除いたものを5に書き込む
　7+) ユーザが追加したテーブル列のうち、リストタイプのもの

・テーブル列は、
　テキスト
　数値
　人
　カレンダー
　リスト
　マイルストーン
タイプがある
マイルストーンタイプはツリー構造を持つリスト

機能要求：
・マインドマップの新規作成、保存、別名保存、削除
・マインドマップの出力: マーメイド形式あるいはPDF形式
・ノードの追加はクリックで　必須項目はタイトルだけ
・マインドマップの広さは無限
・ノードの接続は、ノード同士を順にクリックするだけ
・ノードの接続解除は、接続線を1回クリック→メニューが出て削除を選ぶ
・元に戻す機能
・ノードを1回クリックすると「…」ボタンが出て、それを押すと詳細編集
・マインドマップは、マップ表示と表表示ができる
・表表示では、任意の行に追加可能
・表表示でも同じ操作で接続
・マップ表示では自動並べ替えができる
　-完全自動
　-カレンダー/マイルストーンで上から/左から並べ替え、人/リストタイプの列でグループ化
・ループの検出ができる
・選択したノードからの接続をハイライト
・線のスタイルを変更: 直線、カギ線、曲線
・ノードの一種で「経由点」も置ける　これは接続をクリックしたメニューで選択
・ノードをクリックすると移動用ハンドルが出て、それを持つと移動可能

======

ご提示いただいた要件は、一般的なマインドマップアプリの枠を超えた、「リレーショナルデータベース（RDB）をベースにした高度なビジュアル思考・ナレッジ管理ツール」 のアーキテクチャです。既存の標準的なWebアプリ（MindMeisterやcoggleなど）ではこのスキーマ構造をそのまま満たすものが存在しないため、Web標準技術を用いたカスタムWebアプリ（SPA）として構築する設計が最も確実です。
以下に、実現に向けた全体プランと設計方針をご提案します。
1. 全体アーキテクチャ方針
 * フロントエンド (SPA): HTML5 Canvas / SVG (または React + React Flow / Cytoscape.js)
   * 無限キャンバス、ドラッグ＆ドロップ、ハンドル操作、自動レイアウト（Dagre等）の描画エンジンを構築。
 * ストレージ (バックエンドレス): Google Drive API
   * ユーザー自身のGoogle Drive内にJSONファイル（またはSQLite形式ファイル）として全テーブルデータを1ファイルで保存・同期。
 * データモデル: インメモリRDB（JavaScript側でリレーションシップと変更履歴を保持）
2. データ構造・DB設計プラン
アプリ内部では、各マインドマップごとに以下のようなマルチテーブル構造のJSONとして保持・管理します。
[マインドマップデータ]
├── 1) topic (トピック基本データ + ユーザー定義動的カラム)
├── 2) connection (接続データ + ユーザー定義動的カラム)
├── 3) topic_display (ノード位置・色・形状などの見映え) ※非履歴対象
├── 4) connection_display (線のスタイル・色など) ※非履歴対象
├── 5) history (永続変更履歴)
├── 6) temp_history (Undo/Redo用ローカル一時履歴) ※メモリ上
└── 7+) custom_lists (リスト型・ツリー構造マイルストーンのマスターデータ)

【動的型（カスタム列）の定義】
 * テキスト / 数値 / 人 / カレンダー: 単一値データ
 * リスト: タグ/カテゴリの選択肢マスター（custom_lists）参照
 * マイルストーン: 親ID（parentId）を持たせたツリー構造データ（WBSのような階層構造）
3. 主要機能の実現ロジック
 * Google Drive 連携
   * Google OAuth 2.0 認証を組み込み、専用のアプリデータフォルダ（または任意のフォルダ）へアクセストークンを用いてデータのCRUD処理を実施。
 * ビューの切り替え (マップ ⇔ 表表示)
   * 同一のトピック/接続データモデルを参照し、ビューアー（Canvas/SVGグラフィック ⇔ DataGridテーブル）だけを切り替える構成。
 * 変更履歴 (履歴5・6の分離制御)
   * 操作時: すべての変更（位置移動や色の変更含む）を temp_history にタイムスタンプ付きで記録し、Undo/Redo（元に戻す）を実現。
   * 保存時: temp_history から topic_display / connection_display に起因する差分を取り除いたログのみを抽出して history（永続ログ）へ追加・更新。
 * 自動レイアウト＆ループ検出
   * ループ検出: 接続追加時に深さ優先探索（DFS）または Tarjan のアルゴリズムを用いて閉路（ループ）チェックを実施。
   * グループ化・並べ替え: 選択したカスタム列（カレンダー順、マイルストーンツリー順、人/リストでのクラスタリング）に応じて、トピックをグループ化座標計算してキャンバス上に配置。
 * 経由点（Waypoints）の処理
   * 経由点自体も topic テーブル上は特別な種類のノード（例: type: "waypoint"）として扱い、描画時のみ小さな操作ハンドルとして表示。
4. 開発フェーズ（ロードマップ）
段階的にプロトタイプを作成・検証していくステップをご提案します。
 * フェーズ1: データモデルと描画エンジンの構築
   * JSONスキーマの定義
   * マップ表示（ノード描画、接続、クリック操作、経由点、ハンドル移動）の実装
   * 自動レイアウトとループ検出機能の組み込み
 * フェーズ2: 表表示および動的属性（カスタム列）の対応
   * 表（グリッド）ビューの実装と双方向データ同期
   * カスタム列（カレンダー、マイルストーンツリー、リスト等）の編集機能
 * フェーズ3: 履歴管理とエクスポート
   * Undo/Redo機能（temp_history）の実装
   * 保存時の履歴クリーニング（history への書き込み）
   * Mermaid形式テキスト出力およびPDF出力機能
 * フェーズ4: Google Drive連携と永続化
   * Google API認証処理の実装
   * Google Driveへの新規作成、別名保存、読み込み、削除の実装
